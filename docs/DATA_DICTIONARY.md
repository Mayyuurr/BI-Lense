# BI-Lense Data Dictionary

## Overview
This document specifies the schema, data types, allowable constraints, missing-value strategies, and predictive roles for all tabular data files across the 5 core SME business domains:
1. **Sales & Commercial Demand** (`sales.csv`)
2. **CRM & Customer Supporting Data** (`customers.csv`)
3. **Inventory Health & Stockout Risk** (`inventory.csv`)
4. **Financial Liquidity & Deficit Risk** (`finance.csv`)
5. **HR & Task Delivery Velocity** (`hr.csv`)

---

## 1. Sales & Demand Domain (`sales.csv`)

* **Primary Purpose:** Training and inference for next-period demand prediction ($\hat{Y}_{\text{Demand}, t+1}$) via hybrid ensemble (Random Forest, XGBoost, ANN).
* **Grain:** Daily SKU transaction level.

| Column Name | Data Type | Constraint / Range | Missing Value Strategy | Role | ML Model Relevance | Description |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `transaction_id` | `VARCHAR(64)` | Unique String | Reject / Error | Identifier | None (Ignored) | Primary transaction record key. |
| `date` | `DATE` | `YYYY-MM-DD` | Reject / Error | Metadata | Feature Eng. | Transaction timestamp. |
| `sku_id` | `VARCHAR(32)` | `SKU-001` to `SKU-999` | Reject / Error | Categorical | Target Encoded | Product SKU identifier. |
| `product_category` | `VARCHAR(64)` | 4–6 categories | Mode imputation | Categorical | One-Hot | High-level category (e.g., Hardware, Raw Materials). |
| `units_sold` | `INTEGER` | $\ge 0$ | Impute `0` | Historical | Input Feature | Historical volume sold in this transaction. |
| `unit_price` | `FLOAT` | $> 0.0$ | Median by SKU | Continuous | Input Feature | Standard selling price per unit. |
| `discount_rate` | `FLOAT` | $[0.0, 0.50]$ | Impute `0.0` | Continuous | Input Feature | Discount percentage applied (captures price elasticity). |
| `promotional_flag` | `INTEGER` | $0$ or $1$ | Impute `0` | Binary | Input Feature | Active marketing campaign indicator. |
| `customer_id` | `VARCHAR(32)` | Foreign Key | Impute `CUST-UNKNOWN` | Identifier | Cross-domain | Customer account identifier linking to CRM. |
| `sales_lag_1` | `FLOAT` | $\ge 0.0$ | Forward-fill / `0.0` | Continuous | Input Feature | Unit sales demand from 1 day prior ($t-1$). |
| `sales_lag_7` | `FLOAT` | $\ge 0.0$ | Forward-fill / `0.0` | Continuous | Input Feature | Unit sales demand from 7 days prior ($t-7$). |
| `sales_lag_30` | `FLOAT` | $\ge 0.0$ | Forward-fill / `0.0` | Continuous | Input Feature | Unit sales demand from 30 days prior ($t-30$). |
| `rolling_avg_30` | `FLOAT` | $\ge 0.0$ | 30D Window Mean | Continuous | Input Feature | 30-day moving average volume (smooths noise). |
| `day_of_week` | `INTEGER` | $[0, 6]$ | Derived from Date | Temporal | Input Feature | Day of week ($0 = \text{Monday}, 6 = \text{Sunday}$). |
| `month` | `INTEGER` | $[1, 12]$ | Derived from Date | Temporal | Input Feature | Month of the year. |
| **`next_period_demand`** | `INTEGER` | $\ge 0$ | Reject / Training only | Target ($\hat{Y}$) | **Target Variable** | **Expected unit demand in the next interval ($t+1$).** |

## 2. CRM & Customer Supporting Domain (`customers.csv`)

* **Primary Purpose:** Enriching sales forecasting with customer behavioral metrics and transaction frequencies.
* **Grain:** One row per customer account.

| Column Name | Data Type | Constraint / Range | Missing Value Strategy | Role | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `customer_id` | `VARCHAR(32)` | Unique String | Reject / Error | Identifier | Primary customer identifier. |
| `customer_segment` | `VARCHAR(32)` | `Enterprise`, `Mid-Market`, `Small Biz` | Mode imputation | Categorical | Business classification. |
| `purchase_frequency_index` | `FLOAT` | $[0.0, 10.0]$ | Median imputation | Continuous Feature | Normalized cadence of repeat purchase orders. |
| `avg_order_value` | `FLOAT` | $> 0.0$ | Median imputation | Continuous Feature | Median monetary value per purchase order. |
| `days_since_last_purchase` | `INTEGER` | $\ge 0$ | Impute `999` (Inactive) | Continuous Feature | Recency indicator (higher value $\rightarrow$ churn risk). |
| `total_lifetime_value` | `FLOAT` | $\ge 0.0$ | Impute `0.0` | Continuous Feature | Cumulative revenue generated by this customer. |

## 3. Inventory Health Domain (`inventory.csv`)

* **Primary Purpose:** Predicting probability of stockout prior to supplier delivery ($\hat{Y}_{\text{Stockout}} \in [0, 1]$).
* **Grain:** Daily SKU audit snapshot.

| Column Name | Data Type | Constraint / Range | Missing Value Strategy | Role | ML Model Relevance | Description |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `inventory_record_id` | `VARCHAR(64)` | Unique String | Reject / Error | Identifier | None | Audit record identifier. |
| `date` | `DATE` | `YYYY-MM-DD` | Reject / Error | Metadata | None | Audit snapshot date. |
| `sku_id` | `VARCHAR(32)` | Foreign Key | Reject / Error | Categorical | Target Encoded | Product SKU identifier matching `sales.csv`. |
| `current_stock` | `INTEGER` | $\ge 0$ | Impute `0` | Continuous | Input Feature | Physical units available in warehouse. |
| `reorder_level` | `INTEGER` | $> 0$ | Historical Median | Continuous | Input Feature | Minimum buffer threshold triggering replenishment. |
| `safety_stock` | `INTEGER` | $\ge 0$ | Impute `0` | Continuous | Input Feature | Buffer units allocated for unexpected surges. |
| `supplier_id` | `VARCHAR(32)` | `SUPP-001` to `SUPP-050` | Mode imputation | Categorical | Frequency Encoded | Primary supplier identifier. |
| `lead_time_days` | `INTEGER` | $[1, 45]$ | Median by Supplier | Continuous | Input Feature | Quoted vendor delivery lead time. |
| `historical_delivery_delay_days` | `FLOAT` | $\ge 0.0$ | Impute `0.0` | Continuous | Input Feature | Historical mean delivery delay for this supplier. |
| `inventory_turnover_ratio` | `FLOAT` | $\ge 0.0$ | Median by SKU | Continuous | Input Feature | Stock velocity (COGS / Average Inventory). |
| `predicted_sales_demand` | `FLOAT` | $\ge 0.0$ | Injected from Sales ML | Continuous | Input Feature | **Direct output ($\hat{Y}_{\text{Demand}}$) from Sales ML.** |
| **`stockout_before_delivery`** | `INTEGER` | $0$ or $1$ | Reject / Training only | Target ($\hat{Y}$) | **Target Variable** | **$1$ if buffer depleted to 0 before delivery, $0$ otherwise.** |

## 4. Finance & Liquidity Domain (`finance.csv`)

* **Primary Purpose:** Forecasting probability of 30-day operating cash-flow deficit ($\hat{Y}_{\text{Deficit}} \in [0, 1]$).
* **Grain:** Monthly financial period.

| Column Name | Data Type | Constraint / Range | Missing Value Strategy | Role | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `period_id` | `VARCHAR(16)` | `YYYY-MM` | Reject / Error | Identifier | Monthly accounting cycle key. |
| `date` | `DATE` | `YYYY-MM-DD` | Reject / Error | Metadata | Statement snapshot date. |
| `revenue` | `FLOAT` | $\ge 0.0$ | Median imputation | Input Feature | Total gross revenue generated in this period. |
| `operating_expenses` | `FLOAT` | $\ge 0.0$ | Median imputation | Input Feature | Total operating expenditures (payroll, rent, utilities, vendor bills). |
| `gross_margin_ratio` | `FLOAT` | $[0.0, 1.0]$ | Derived: $(\text{Rev} - \text{COGS})/\text{Rev}$ | Input Feature | Gross profit percentage. |
| `net_margin_ratio` | `FLOAT` | $[-1.0, 1.0]$ | Derived: $\text{NetIncome}/\text{Rev}$ | Input Feature | Net profit margin after all deductions. |
| `liquid_cash_reserves` | `FLOAT` | $\ge 0.0$ | Median imputation | Input Feature | Readily accessible bank and cash balances. |
| `accounts_receivable` | `FLOAT` | $\ge 0.0$ | Median imputation | Input Feature | Total outstanding unpaid invoices. |
| `ar_aging_over_45_days` | `FLOAT` | $\ge 0.0$ | Impute `0.0` | Input Feature | Delayed customer receivables (primary risk indicator). |
| `debt_to_equity_ratio` | `FLOAT` | $\ge 0.0$ | Median imputation | Input Feature | Financial leverage and solvency ratio. |
| `monthly_burn_rate` | `FLOAT` | $\ge 0.0$ | Derived: Monthly Net Cash Outflow | Input Feature | Rate of cash consumption per month. |
| **`cash_deficit_30d`** | `INTEGER` | $0$ or $1$ | Reject / Training only | **Target Variable** | **$1$ if liquid cash < next 30-day OpEx obligations, $0$ otherwise.** |

## 5. HR & Operational Productivity Domain (`hr.csv`)

* **Primary Purpose:** Predicting projected task delivery delay duration / backlog risk ($\hat{Y}_{\text{Delay}}$).
* **Grain:** Weekly team/employee log.

| Column Name | Data Type | Constraint / Range | Missing Value Strategy | Role | Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `log_id` | `VARCHAR(64)` | Unique String | Reject / Error | Identifier | Periodic productivity log key. |
| `employee_id` | `VARCHAR(32)` | `EMP-001` to `EMP-100` | Reject / Error | Identifier | Employee identifier. |
| `department` | `VARCHAR(32)` | `Engineering`, `Operations`, `Sales`, `Logistics` | Mode imputation | Categorical | Assigned organizational unit. |
| `tasks_assigned` | `INTEGER` | $\ge 0$ | Impute `0` | Input Feature | Number of work items assigned in this cycle. |
| `tasks_completed` | `INTEGER` | $\ge 0$ | Impute `0` | Input Feature | Work items finished on-time. |
| `avg_completion_time_days` | `FLOAT` | $> 0.0$ | Median by Dept | Input Feature | Mean turnaround time per work item. |
| `absenteeism_rate` | `FLOAT` | $[0.0, 1.0]$ | Impute `0.0` | Input Feature | Fraction of scheduled working hours missed. |
| `workload_density_ratio` | `FLOAT` | $> 0.0$ | Derived: $\text{Assigned}/\text{Completed}$ | Input Feature | Work in progress density. |
| `team_performance_index` | `FLOAT` | $[0.0, 100.0]$ | Median by Dept | Input Feature | Composite rating of team execution velocity. |
| **`task_delay_days`** | `FLOAT` | $\ge 0.0$ | Reject / Training only | **Target Variable** | **Expected task delivery slippage in business days beyond deadline.** |

## 6. Deterministic Preprocessing and Schema Validation Rules

1. **Header Coercion:** All column headers are trimmed and converted to lowercase `snake_case`.
2. **Deduplication:** Duplicate transaction IDs or exact row matches are dropped during ingestion.
3. **Out-of-Range Handling:** Continuous features are clipped to operational minimum/maximum thresholds before MinMax scaling.
4. **Reproducibility Guarantee:** All deterministic transformations are executed via Python/Pandas (`app/data/preprocessing/cleaner.py`), while LLaMA provides schema mapping suggestions only.
